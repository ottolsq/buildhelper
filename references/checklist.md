# 交付前清单

逐条勾。勾不动的不要打勾，改成「不做 + 理由」。

## 立项

- [ ] `goal.md` 的「非目标」非空，且能挡住至少一个诱惑
- [ ] 成功标准有可测的指标，不是「体验好」
- [ ] `architecture.md` 的组件表和代码目录对得上
- [ ] `AGENTS.md` 保留了用户已有的协作约定，路径可移植，每条可用命令有实测依据；尚无可运行入口时如实标明

## 里程碑

- [ ] `plan.md` 只有本期范围，没有下一期的任务
- [ ] DoD 每一条都能被第三个人验证
- [ ] 风险有触发信号，不只是「可能延期」

## 发版

- [ ] README 的快速开始能在干净环境复现
- [ ] `CHANGELOG.md` 与 plan 的里程碑对应
- [ ] 破坏性变更写了迁移方式
- [ ] 测试记录有放行结论和批准人

## 提交与实际验收

- [ ] 用 `git diff --cached` 核对本批逻辑范围和实际暂存内容。个人路径、设备标识、原始日志和凭据留在本地。
- [ ] 独立模块的测试结论写清输入和结果。有可体验流程时已邀请用户试用，记录用户实际看到的现象。用户暂不试用且同意提交时，功能状态写「已实现，待实际验证」。

## 文档交付或审计（纯代码改动按项目要求自测）

- [ ] 没有 `<!-- fill -->` 残留
- [ ] 没有断链（`check_docs.py` 无 WARN）
- [ ] 看过 `config` 行：用的是项目自己的配置，不是基础默认值套错了项目
- [ ] 看过 `scan` 行：跳过的是真的不该扫，不是漏扫
- [ ] 文档里的命令 = 清单文件里的脚本名
- [ ] 用户需要的共享文档可从 README 找到，链接目标随仓库发布
- [ ] ADR 编号唯一且递增
- [ ] 文档入库时按需用 `--staged` 检查文件范围，已核对其中的跳过提示和暂存差异
- [ ] 没有疑似凭据（`check_docs.py` 的凭据命中已逐条确认，不是靠占位符绕过）
- [ ] 整理文档时运行 `--inventory`，确认新增文件有唯一归属
- [ ] `duplicate scope` 与 `budget` 的告警已处理：合并、归档，或写明为什么保留
- [ ] 已经放进归属目录的文档在 `--inventory` 里应显示 `keep`；仍是 `review` 说明 `scopes` 缺这个允许位置，先补规则再判文件

## 存量整理（用户明确要求时才做）

- [ ] 盘点来自全量 `*.md`，不是 README 索引
- [ ] 先跑 `--inventory`，把 keep / merge / archive / review 表格交给用户
- [ ] 每份文档都归到「保留 / 合并 / 仅本地 / 删除」之一
- [ ] 每个「删除」都写明了结论去处，且引用已更新
- [ ] 归档目录没有被当成垃圾桶
- [ ] 改动前给出清单并得到确认，范围外未动

## 复盘

- [ ] 根因停在机制层，不停在「有人忘了」
- [ ] 「本该拦住它的地方」逐层填过，不是全塞给 AGENTS.md
- [ ] 至少有一条落到了自动化，而不只是文档
