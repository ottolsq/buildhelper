# 目标与范围

## 问题

新项目的文档通常死在两个极端：要么一份不写，要么立项时一口气写十几份，两周后全部过期还占着位置。中间那层判断——「现在这个阶段该有哪份、写到什么程度、什么时候必须更新」——没人写下来，于是每个项目重新踩一遍。

用 agent 开发时更明显：agent 不知道项目处在哪个阶段，要么不写，要么生成一堆看着完整、实则全是占位符的文件。

## 用户

- 用 agent 从零做项目的个人开发者
- 需要接手他人项目、想把文档规范一次的小团队

## 目标

- 把「阶段 → 该产出什么」固定成流程，让 agent 不必每次自己判断
- 产出必须可校验：缺文件、缺章节、断链、编号重复都能自动发现
- 新项目立项时 15 分钟内得到可用骨架，而不是一堆空表格

## 非目标

- 不做文档托管、不做静态站点生成
- 不替代 issue 跟踪：`FIXME` / `TODO` 不进文档体系
- 不生成「看上去完整」的占位文档——信息不足时必须停下来问
- 不绑定具体技术栈

## 成功标准

| 指标 | 目标 | 怎么测 |
|---|---|---|
| 立项耗时 | ≤ 15 分钟 | 在空仓库跑一遍 |
| 校验可执行 | 一条命令，退出码可用 | 正反用例各一次 |
| 一个月后文档仍在更新 | 至少 plan / ADR 有真实变更 | 看 git 历史 |

## 约束

- 校验脚本跨平台：Windows / macOS / Linux 同一份，只用 Python 3.8+ 标准库，不装依赖
- 不改 DSH 本体，只做 skill 包
- 无网络也能用

## 开放问题

- 校验是否需要 `-Stage` 参数，按立项 / 里程碑 / 发版校验不同文件集
